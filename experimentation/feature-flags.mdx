title: "Feature flags"
description: "A feature flag is a layer with one parameter. Switch it on, roll it out, or test it — the same primitives, created in one step."
---

A feature flag in Traffical isn't a separate object. It is a [layer](/concepts/layers) that holds exactly one [parameter](/concepts/parameters). The parameter's default is the **off** value. Turning the flag on starts a [policy](/concepts/policies) that serves the **on** value to every user in the layer. Rolling out narrows that policy to a share of users. Testing adds a second policy with more than one allocation. Every step uses the model the rest of the platform uses, so a flag never has to be migrated into an experiment.

## Create a flag

In the dashboard, open **Layers** and pick **Feature flag** from the **New layer** menu. The dialog asks for:

- **Flag name** — the layer's name. The key is derived from it.
- **Key** — what your code reads, as a `snake_case` suffix under a parameter group. `checkout.social_proof` is the group `checkout` plus the suffix `social_proof`; the `main` group has no prefix.
- **Type** — `boolean` by default. A `string` or `number` flag can carry **allowed values**, which turns it into an enum such as `legacy | v2 | hybrid`.
- **Off value** — the parameter default, what everyone gets while the flag is off.
- **On value** — what the **On** policy serves.
- **Turn on now** — creates the On policy running instead of as a draft.

One call creates the layer, the parameter, and the On policy together. The footer of the dialog states exactly what will be created, and the confirmation shows the three objects with their state.

Flags are also defined by the [config file](/tools/config-file) as a boolean parameter with a default. Creating the layer and policy is a dashboard or API step.

## Read it in code

Nothing about the SDK changes. A flag is a parameter:

```typescript
const { params } = useTraffical({
  defaults: { "checkout.social_proof": false },
});

if (params["checkout.social_proof"]) {
  return <SocialProof />;
}
```

If Traffical is unreachable, the default in code is what your application sees.

## Switch it on and off

Turning a flag on means the **On** policy is running. Turning it off means it is paused. Either way, every user gets the parameter's default while nothing runs. Because on and off are policy transitions, they carry the same audit trail and, where your organization has configured them, the same [approvals](/governance/approvals-and-autonomy) as any other policy start.

The parameter's default stays the off value. Changing the default changes what every policy in the layer treats as the baseline, so use it to change what "off" means, not as the switch.

## Target it

Add [targeting conditions](/concepts/policies#targeting-conditions) to the On policy to serve the on value only to users whose context matches: a plan, a country, a list of user ids. A flag's On policy is created with targeting declared as a **live edit**, so the conditions can change while the flag is on. Each change asks for a reason and lands on the audit trail and the policy's decision log. The setting lives on the policy's Settings tab under **Live edits**; an A/B test on the same parameter does not get it, because changing who is measured mid-flight would invalidate the comparison.

## Roll it out gradually

Narrow the On policy's allocation to a share of the layer and widen it over time with a [rollout](/experimentation/rollouts). Users inside the range get the on value; everyone else keeps the default. Health checks can pause or roll back the ramp before a human notices.

## Test it

Add a policy with two allocations to the flag's layer, one serving the off value and one serving the on value. That policy is an [A/B test](/experimentation/ab-testing) on the flag: same parameter, same layer, same SDK code. When the test is done, complete it and start the On policy with the winning value.

## Kill switches

A kill switch is a flag whose off value is `true`. The On policy serves `false`, and you keep it as a draft until you need it. Starting it turns the feature off for every user within the SDK's refresh interval (default 60s). For a faster guarantee, reduce `refreshIntervalMs` on the client.

## Enum flags

A `string` flag with allowed values `legacy`, `v2`, and `hybrid` is one parameter that can take three values. Off is one of them, on is another, and a test can compare all three. The allowed values are enforced on every policy that overrides the parameter.

## When a flag is not enough

If you find yourself adding more booleans to control one feature (`show_new_layout`, `use_new_copy`, `apply_new_discount`), create a **Standard** layer instead and give it several typed parameters:

```yaml
parameters:
  checkout.layout:        { type: string,  default: "classic" }
  checkout.headline:      { type: string,  default: "Complete your order" }
  checkout.discount_pct:  { type: number,  default: 0 }
```

One policy overrides all three together, and one A/B test compares the combinations without three correlated booleans posing as one test. A flag layer is not locked either: you can add parameters and policies to it later.
